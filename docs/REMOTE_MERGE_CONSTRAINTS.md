# 远程代码合并约束

本文档用于约束从原仓库合并更新到当前二开仓库的流程。执行远程合并前必须先阅读并遵守本文件，合并过程中以保护当前 `ManScan` 二开功能和现有系统稳定性为最高优先级。

## 分支范围

- 远程合并仅允许在本地 `upstream` 分支上执行。
- 不得在 `upstream` 之外的任何本地分支执行远程更新合并、变基、重置、挑拣或冲突落盘操作。
- 不得修改、重置、删除或强推当前二开开发分支、主分支、发布分支或其他业务分支。
- 如需把合并后的结果应用到其他分支，必须先完成 `upstream` 分支合并和验收，再由用户明确确认后单独处理。

## 二开代码保护

- 当前仓库是基于原仓库的二开版本，合并远程更新时不得覆盖、删除或弱化本地已经新增的功能、代码、配置、文档和运行行为。
- 合并前和冲突处理过程中，可以参考项目根目录 `CHANGE.md` 查看本地二开记录、历史改动目的和已形成的功能约定。
- 对本地已有功能存在冲突时，必须优先保留 `ManScan` 当前行为；只有在确认远程改动是必要修复且不会破坏二开能力时，才可以合入对应逻辑。
- 对历史二开改动必须重点保护，包括但不限于：
  - 本地模块名和内部引用路径使用 `ManScan`。
  - 默认运行数据目录收口到项目 `data/`。
  - 默认关闭更新检查和移除更新提示。
  - 模板签名验证调整。
  - 服务端、扫描运行时、前端日志适配、自动模板映射、暂停恢复、请求链记录等本地增强能力。
- 遇到远程代码与二开代码语义不一致时，不得简单采用远程版本覆盖本地实现，必须逐项分析影响并保留兼容方案。

## 现有功能保护

- 远程新增代码不得影响当前系统已经可用的功能，也不得破坏二开新增功能。
- 合并后必须对受影响模块进行必要的构建、测试或静态检查；无法执行时，需要在合并更新文档中明确说明原因和风险。
- 对涉及扫描执行、模板加载、进度统计、暂停恢复、结果输出、服务端接口、数据目录、配置初始化的远程改动必须重点审查。
- 如果远程新增逻辑引入外部网络访问、自动更新、默认目录变化、签名限制恢复、输出格式变化或接口行为变化，必须确认不会改变 `ManScan` 当前约定后才能保留。

## Import 路径约束

- 本地 Go 模块名为 `ManScan`。
- 远程代码中新增或恢复的内部包引用如果使用 `github.com/projectdiscovery/nuclei/v3` 或 `github.com/projectdiscovery/nuclei`，在本地必须改为对应的 `ManScan` 引用。
- 不得让业务代码重新依赖原仓库内部模块路径，避免构建时解析到外部模块或破坏本地模块边界。
- 第三方依赖不属于内部包引用时，可按实际依赖关系保留，但必须确认不是原仓库内部包路径误引入。

## 已删除文件保护

- 本地已经删除的文件，远程合并时不得无条件重新新增。
- 只有当该文件对当前系统构建、运行、测试或远程更新中的必要功能确实不可缺少时，才允许恢复。
- 恢复已删除文件前必须说明必要性，并检查文件内容是否需要按 `ManScan` 本地约定调整。
- 对远程新增但本地历史已删除且非必要的文件，应继续保持删除状态。

## 冲突处理要求

- 处理冲突时必须逐文件阅读上下文，区分远程修复、本地二开能力和两者可兼容的部分。
- 不得用 `--theirs` 或类似方式批量覆盖本地改动。
- 不得用 `--ours` 或类似方式无差别丢弃远程更新。
- 对无法判断影响的冲突，应停止处理并向用户说明冲突点、可能影响和建议选择。
- 所有冲突解决完成后，必须再次检查是否出现原仓库模块路径、被删除文件恢复、二开功能被覆盖或默认行为被远程改回。

## 合并后更新文档

每次远程合并完成后，必须生成一份详细的合并更新 Markdown 文档，建议路径为：

```text
docs/remote-merge-updates/YYYY-MM-DD-upstream-merge.md
```

文档至少包含：

- 本次合并来源：远程名称、远程分支、提交范围或提交列表。
- 本次合并目标：确认仅在本地 `upstream` 分支处理。
- 远程新增、修改、删除的主要内容。
- 与 `ManScan` 二开代码发生冲突或需要适配的内容。
- 对 `github.com/projectdiscovery/nuclei` 相关 import 的本地化处理结果。
- 本地已删除文件是否被远程尝试恢复，以及最终处理决定。
- 为保护现有系统功能采取的兼容措施。
- 执行过的构建、测试、静态检查命令及结果。
- 未验证项、保留风险和后续建议。

## 合并前后检查清单

- 确认当前操作分支是本地 `upstream`。
- 确认不会修改其他本地分支。
- 确认已记录合并前工作区状态。
- 参考 `CHANGE.md` 梳理本地二开记录和需要重点保护的历史改动。
- 合并后搜索并处理 `github.com/projectdiscovery/nuclei` 内部 import。
- 合并后检查本地二开功能相关文件是否被远程覆盖。
- 合并后检查本地已删除文件是否被重新新增。
- 合并后执行必要的构建或测试。
- 合并后生成详细更新文档。
